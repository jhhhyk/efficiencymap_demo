## 역할

빌드 도구나 프레임워크 없이 동작하는 정적 사이트입니다. 매물 데이터를 GeoJSON 정적 파일로 직접 읽어 지도에 렌더링하므로, 백엔드 없이도 다음 기능이 동작합니다.

- 매물 분포 확인
- 소요시간 / 효율 모드 전환
- 시간 기준 필터링
- 매물 상세 정보 조회

백엔드가 필요한 기능은 **상세 경로 조회** 하나입니다.

## 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 언어 | JavaScript (Vanilla, ES5+) |
| 지도 | Leaflet 1.9 |
| 타일 | CARTO Basemaps (Positron) |
| 스타일 | CSS Custom Properties |
| 빌드 | 없음 (정적 파일) |

기본 지도 타일로 밝은 회색 계열의 Positron을 사용합니다. 지도 자체의 색상 정보가 적어 매물 마커의 6단계 색상 스케일이 배경과 혼동되지 않습니다.

## 파일 구조

```
frontend/
├── index.html
├── css/
│   ├── tokens.css      디자인 토큰 (CSS 변수)
│   └── style.css       컴포넌트 스타일
├── js/
│   ├── config.js       상수, 공유 상태, 유틸리티
│   ├── map.js          지도 초기화, 마커 생성, 클러스터링
│   ├── route.js        경로 요청 및 폴리라인 렌더링
│   └── ui.js           사이드바, 범례, 모드 토글, 필터
└── data/
    └── data.json       매물 5,073건 (GeoJSON)
```

스크립트는 ES 모듈이 아닌 클래식 스크립트로 로드하며, `config → map → route → ui` 순서로 읽습니다.

## 데이터 시각화 규칙

### 색상 스케일

두 가지 분석 모드를 제공하며, 모드에 따라 마커 색상의 기준이 달라집니다.

**시간 모드** — 기대 소요시간 기준 고정 구간

| 구간 | 색상 | 토큰 |
|---|---|---|
| 0–10분 | 초록 | `--color-scale-1` |
| 10–15분 | 연두 | `--color-scale-2` |
| 15–20분 | 노랑 | `--color-scale-3` |
| 20–25분 | 주황 | `--color-scale-4` |
| 25–30분 | 빨강 | `--color-scale-5` |
| 30분 이상 | 보라 | `--color-scale-6` |
| 데이터 없음 | 회색 | `--color-scale-na` |

**효율 모드** — 효율지수 기준 5분위 구간

전체 매물의 효율지수 분포를 백분위로 나누어 구간을 동적으로 계산합니다. 효율지수는 절대값의 범위가 넓고 지역별 편차가 크기 때문에, 고정 구간보다 상대 분포가 해석에 유리합니다.

| 구간 | 의미 |
|---|---|
| 상위 20% | 매우 좋음 — 고효율 저평가 매물 |
| 20–40% | 좋음 |
| 40–60% | 보통 |
| 60–80% | 나쁨 |
| 하위 20% | 매우 나쁨 — 고평가 매물 |

**설계 의도** — 두 모드 모두 녹색에서 적색으로 이어지는 그라디언트를 사용해, 별도의 학습 없이 "녹색이 좋다"는 직관이 통하도록 했습니다.

## 마커 클러스터링

매물 5,073건을 개별 마커로 모두 그리면 브라우저 부하가 커지고, 시각적으로도 밀집 구역의 색상 구분이 불가능해집니다. 이를 해결하기 위해 줌 레벨에 따라 표현 방식을 전환합니다.

### 전환 규칙

| 조건 | 표시 방식 |
|---|---|
| 줌 ≤ 15 | 클러스터 마커 |
| 줌 ≥ 16 | 개별 도트 마커 |
| 화면 내 매물 3,000건 초과 | 클러스터 마커 (줌 무관) |
| 필터 활성화 | 개별 도트 마커 (항상) |
| 격자 내 매물 1건 | 개별 도트 마커 |
| 선택된 매물 | 전용 마커 (클러스터에서 제외) |

필터가 켜진 상태에서 클러스터링을 끄는 이유는, 필터링 후 남은 매물 수가 적어 개별 표시가 가능하고 사용자가 조건에 맞는 매물의 정확한 위치를 확인하려 하기 때문입니다.

### 그룹화 방식

지리적 거리가 아닌 **화면 픽셀 좌표 기준 80×80 격자**로 묶습니다.

```
1. 화면에 보이는 매물의 좌표를 픽셀 좌표로 변환
2. 80px 격자 단위로 분할해 같은 격자의 매물을 하나로 묶음
3. 클러스터 위치는 격자 내 매물 좌표의 평균
4. 클러스터 클릭 시 현재 줌 +2 (최대 17)로 확대 이동
```

거리 기반이 아닌 화면 기준으로 묶기 때문에, 줌 레벨이 달라져도 **화면상 시각 밀도가 일정하게 유지**됩니다. 확대할수록 격자가 커버하는 실제 면적이 줄어들어 자연스럽게 클러스터가 분해됩니다.

지도 이동·확대 시(`moveend`, `zoomend`)마다 화면 범위 내 매물만 다시 계산하므로, 화면 밖 매물은 렌더링 대상에서 제외됩니다.

초기 줌 레벨은 14입니다.

## 화면 구성

### 지도

전체 화면을 차지하는 기본 레이어입니다. 매물 마커, 클러스터 마커, 경로선, 정류장 마커가 이 위에 표시됩니다.

### 사이드바 정보 패널

매물 선택 시 좌측에서 슬라이드 인됩니다.

| 영역 | 내용 |
|---|---|
| 헤더 | 건물명, 닫기 버튼 |
| 배지 | 건물 용도 (다세대주택, 오피스텔 등) |
| 기본 정보 | 주소, 보증금/월세, 전용면적 |
| 이동 정보 | 이용 노선, 단계별 소요시간 |
| 강조 | 배차간격을 고려한 기대 소요시간 |
| 분석 지표 | 효율지수 |

단계별 소요시간은 `🚶 2분 → 🚌 9분 → 🚶 7분` 형태로 표시해, 전체 소요시간이 어떤 구간으로 구성되는지 바로 파악할 수 있게 했습니다. 도보만으로 이동하는 매물은 대중교통 구간 없이 도보 시간만 표시합니다.

경로를 조회하는 동안에는 이동 정보·강조·분석 지표 영역이 로딩 표시로 대체됩니다.

### 범례

지도 우하단에 고정되며, 현재 모드에 따라 표시 내용이 바뀝니다. 시간 모드는 6개 구간, 효율 모드는 5개 구간을 색상 견본과 함께 나열합니다.

### 모드 토글

범례 하단의 세그먼트 컨트롤로 시간·효율 모드를 전환합니다. 전환 시 모든 마커 색상과 범례가 함께 갱신됩니다.

### 필터 컨트롤

지도 좌하단의 원형 버튼이며, 클릭하면 가로로 확장되면서 슬라이더가 나타납니다. 기대 소요시간 상한을 설정해 해당 조건을 만족하는 매물만 표시합니다.

사용자 조사에서 통학 시간 상한선을 30분 이하로 설정한 응답자가 90.3%였던 점을 반영해, 본인의 한계 통학 시간에 맞춰 범위를 좁혀가는 탐색 방식을 지원합니다.

## 경로 시각화

매물을 선택하면 목적지까지의 경로가 **세 구간으로 나뉘어** 표시됩니다.

| 구간 | 색상 | 두께 | 선 종류 |
|---|---|---|---|
| 승차 정류장까지 도보 | `--color-text-primary` | 2 | 점선 (4/6) |
| 대중교통 | `--color-brand-primary` | 3 | 실선 |
| 하차 후 목적지까지 도보 | `--color-text-primary` | 2 | 점선 (4/6) |

대중교통 구간만 실선·두꺼운 선·강조 색상을 사용해, 이동의 주된 수단이 어디인지 한눈에 구분됩니다. 이 세 구간은 사이드바의 단계별 소요시간 표시와 1:1로 대응합니다.

경로선의 좌표는 백엔드가 반환한 실제 도로 형상 좌표를 연결해 그리므로, 직선이 아닌 실제 노선을 따라갑니다.

### 정류장 표시

| 요소 | 색상 |
|---|---|
| 승차 정류장 라벨 | `--color-brand-primary` |
| 하차 정류장 라벨 | `--color-brand-danger` |

정류장 이름을 말풍선 형태로 함께 표시합니다.

### 폴백 처리

경로 조회가 실패하거나 백엔드가 없는 경우, 출발지에서 목적지까지 직선 점선을 그리고 도보 기준 정보를 표시합니다. 정보가 아예 없는 것보다 최소한의 위치 관계라도 제공하는 편이 낫다는 판단입니다.

## 반응형

브레이크포인트는 `768px` 하나입니다.

| | 데스크톱 (>768px) | 모바일 (≤768px) |
|---|---|---|
| 정보 패널 | 좌측 고정 사이드바 (320px) | 하단 시트 (높이 45vh) |
| 진입 방향 | 좌측에서 슬라이드 인 | 하단에서 슬라이드 업 |
| 모서리 | 직각 | 상단 모서리 라운드 |

지도 위 플로팅 요소(범례, 모드 토글, 필터)는 `position: fixed`로 화면 모서리에 고정되므로, 브라우저 창 크기가 바뀌어도 위치가 유지됩니다.

모바일에서는 하단 시트가 열려도 플로팅 요소를 별도로 숨기지 않으며, 시트에 가려지는 것이 의도된 동작입니다.

## 디자인 시스템

색상과 간격 등의 시각 속성을 하드코딩하지 않고, Figma에 정의된 디자인 토큰을 CSS 커스텀 프로퍼티로 대응시켜 관리합니다.

### Figma 파일 구조

| 페이지 | 내용 |
|---|---|
| Tokens | 색상·간격·모서리·타이포·그림자 토큰 명세 |
| Assets | 컴포넌트 21종 |
| Screens | 화면 프레임 12종 (데스크톱 8, 모바일 4) |

### 토큰

`css/tokens.css`

| 분류 | 개수 | 접두사 |
|---|---|---|
| 색상 | 32 | `--color-*` |
| 간격 | 10 | `--space-*` |
| 모서리 | 5 | `--radius-*` |
| 그림자 | 8 | `--shadow-*` |
| 텍스트 스타일 | 10 | `.text-*` |

Figma 변수의 이름 규칙(`color/text/primary`)이 CSS 변수명(`--color-text-primary`)과 1:1로 대응하도록 code syntax를 지정해, 양쪽의 이름이 어긋나지 않게 했습니다.

### 2단 구조

색상 32개는 원시(primitive) 23개와 의미(semantic) 9개 두 계층으로 분리했습니다.

```css
/* Primitive — 실제 색상값 */
--color-neutral-900: #111827;
--color-neutral-500: #6b7280;
--color-brand-primary: #2563eb;

/* Semantic — 용도를 가리키는 참조 */
--color-text-primary:   var(--color-neutral-900);
--color-text-tertiary:  var(--color-neutral-500);
--color-text-accent:    var(--color-brand-primary);
```

의미 계층은 `text/*`, `surface/*`, `border/*` 세 갈래이며, 각각 원시 계층의 `neutral/*` 또는 `brand/*`를 참조합니다.

| 의미 토큰 | 참조 대상 |
|---|---|
| `--color-text-primary` | `--color-neutral-900` |
| `--color-text-secondary` | `--color-neutral-700` |
| `--color-text-tertiary` | `--color-neutral-500` |
| `--color-text-disabled` | `--color-neutral-400` |
| `--color-text-accent` | `--color-brand-primary` |
| `--color-surface-page` | `--color-neutral-bg` |
| `--color-surface-card` | `--color-neutral-0` |
| `--color-surface-muted` | `--color-neutral-100` |
| `--color-border-default` | `--color-neutral-200` |

컴포넌트는 semantic 토큰만 사용합니다. 본문 글자색을 조정할 때 `--color-text-primary` 한 곳만 바꾸면 이를 참조하는 모든 요소에 반영됩니다.

지도 위 플로팅 요소는 반투명 배경이 필요해 `--color-surface-floating`(흰색 95%)을 별도로 두었습니다.

### 컴포넌트

Figma 컴포넌트 21종을 정의했으며, 상태 변화는 Variants로 관리합니다.

| 분류 | 컴포넌트 |
|---|---|
| 마커 | DotMarker(7종), ClusterMarker, SelectedMarker, DestinationMarker, StopDot, StationLabel(2종) |
| 플로팅 | LegendCard(2종), LegendRow, ModeToggle(2종), FilterFAB(2종), Slider |
| 패널 | SidebarHeader, Badge, InfoRow(2종), RouteSummary(2종), HighlightRow, Divider, LoadingRow, LoadingSpinner |
| 레이아웃 | Sidebar, BottomSheet |

Figma 컴포넌트명과 CSS 클래스명을 대응시켜 관리합니다.

| Figma | CSS |
|---|---|
| `DotMarker` | `.dot`, `.dot--1` ~ `.dot--6` |
| `ClusterMarker` | `.cluster-marker` |
| `StationLabel` | `.station-label`, `.station-root-dot` |
| `LegendCard` | `#legend`, `.lg-row` |
| `ModeToggle` | `#mode-toggle`, `.seg-btn` |
| `Sidebar` | `#sidebar`, `.sb-header`, `.sb-row` |

JavaScript에서도 색상값을 직접 지정하지 않습니다. 마커 색상은 `.dot--1` ~ `.dot--6` 클래스로 적용하고, 경로선처럼 값을 직접 넘겨야 하는 경우에는 `getComputedStyle`로 CSS 변수를 읽어옵니다.

```js
const color = getComputedStyle(document.documentElement)
  .getPropertyValue('--color-brand-primary');
```

## 실행 방법

정적 파일이므로 빌드 과정이 없습니다.

```bash
cd frontend
python -m http.server 5500
```

브라우저에서 `http://localhost:5500` 접속.

경로 조회 기능까지 사용하려면 [백엔드](../backend/README.md)를 함께 실행해야 합니다. 백엔드가 응답하지 않으면 안내 배너가 표시되며, 나머지 기능은 정상 동작합니다.

`js/config.js`의 `API_BASE`가 접속 환경에 따라 백엔드 주소를 자동으로 선택합니다.
